## 实验报告：向量场群体寻路算法 (Flow Field Pathfinding)

### 1. 实验背景与目的
在 RTS、塔防及“类吸血鬼幸存者”等游戏中，同屏常出现成百上千的单位需要寻路。如果为每个单位独立运行传统的 A* 算法（时间复杂度 O(N)），会导致严重的 CPU 算力瓶颈，引发卡顿和单位移动不自然。本实验旨在引入并实现**向量场群体寻路算法**，通过将寻路计算从“个体”转移到“环境地图”，以空间换取极致的时间效率（复杂度 O(G)，G 为网格数），实现海量单位的流畅移动。

### 2. 实验核心原理与步骤
算法实现主要分为以下几个关键步骤：
1. **构建热力图 (Integration Field)**：
   - 使用广度优先搜索 (BFS) 算法，从目标点向外围扩散。
   - 累加地形移动代价 (Cost)，绕开障碍物，生成一张记录每个网格到目标点累积距离成本的“热力图”。
2. **生成向量场 (Vector Field)**：
   - 遍历每个网格，对比其相邻的 8 个方向的成本。
   - 生成一个指向最低成本方向的单位向量。全图网格的向量汇聚在一起，形成指引单位移动的“水流”。
3. **双线性插值 (Bilinear Interpolation)**：
   - 为避免单位跨越网格时产生生硬的折线转向，算法计算单位距离周围 4 个网格中心的权重，进行双线性插值，得出平滑的引导力。
4. **分离避障与障碍物规避 (Separation & Avoidance)**：
   - **单位间斥力**：单位只检测感知半径 (Perception Radius) 内的邻居，距离越近产生的斥力越大，防止单位重叠穿模。
   - **障碍物斥力**：在单位即将撞上物理障碍时提前施加法向推力，使其平滑绕行。
5. **修复对角线穿模卡死**：
   - 在生成向量场时引入“相邻墙壁”判定。如果水平或垂直方向有障碍物，禁止对角线方向的通行指引，彻底解决单位卡死在对角线夹角的 Bug。

### 3. 工程化与部署实施
1. **环境初始化**：使用 `Vite + React` 搭建本地工程，替代单文件结构。
2. **依赖引入**：集成 `Lucide React` (图标)、`Framer Motion` (动画) 和 `Tailwind CSS` (样式)。
3. **代码重构**：将 Canvas 逻辑模块化，在 `App.jsx` 中统一管理 Canvas 渲染循环、状态与用户交互（如通过滑块实时调节斥力）。
4. **自动化部署**：配置 `vite.config.js` 的 base 路径，使用 `gh-pages` 脚本实现一键自动化部署至 GitHub Pages。

### 4. 实验结论
通过本次实验，成功实现了向量场群体寻路算法的原型并完成工程化。实验证明：
- 向量场算法在处理海量寻路单位时，性能表现远优于传统独立寻路算法。
- 结合双线性插值与局部避障（Steering Behaviors），单位展现出了如水流般自然顺滑的群体移动特征。
- 利用 AI (Gemini) 辅助生成核心逻辑原型，并结合现代前端工程化工具，极大提升了从算法概念到可交互 Demo 产品的落地效率。
